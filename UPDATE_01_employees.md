# Оновлення 1 — Працівники + облік кожного авто окремо

## Що нового

1. **Робочий день** повністю переосмислений:
   - Більше не вводиш вручну "дохід" і "к-сть авто" за день.
   - Замість цього додаєш **кожне авто окремим записом**: послуга (той самий
     список, що й у "Запис"), марка/модель авто, тип кузова (Легкова,
     Універсал, Кроссовер, Бус), ціна, і, за бажанням, працівник.
   - Дохід, кількість авто і виплати працівникам за день рахуються
     автоматично.
   - Витрати за день і далі вводяться вручну (окреме поле).
   - Внизу — швидкий перехід по останніх днях.

2. **Нова вкладка "Працівники"**:
   - Додавання працівника з ім'ям, телефоном і відсотком від виконаної
     роботи.
   - Клік на картку працівника відкриває детальну статистику: скільки
     заробив, скільки авто помив, скільки доходу приніс мийці — з
     перемикачем **Сьогодні / Тиждень / Місяць**.
   - Список останніх авто цього працівника з сумою виплати за кожне.

3. При додаванні авто у "Робочому дні" з обраним працівником — відсоток
   і сума виплати **фіксуються на момент запису** (знімок). Якщо пізніше
   зміниш відсоток працівника, минулі записи не перерахуються заднім
   числом — це важливо для чесної історії виплат.

## Крок 1. Онови базу даних у Supabase (обов'язково, перед кодом)

1. Зайди в Supabase Dashboard → **SQL Editor → New query**.
2. Відкрий файл `supabase/migration_02_employees_and_cars.sql` з цього
   архіву, скопіюй **весь** вміст, встав у редактор.
3. Натисни **Run**.

Це доповнення до бази — воно **не видаляє** жодних існуючих даних, лише
додає дві нові таблиці (`employees`, `car_entries`) і налаштовує
автоматичний перерахунок доходу/к-сті авто через тригер.

⚠️ Якщо в тебе вже є тестові записи в "Робочому дні" з ручним доходом —
вони залишаться як є, доки ти не почнеш додавати авто через новий
інтерфейс за ту саму дату (тоді дохід за цю дату перерахується на основі
доданих авто).

**не видаляй свій `.env`**, він у цьому архіві теж є, але з
прикладовими значеннями — постав туди назад свої справжні ключі, якщо
переносиш вручну.

## Крок 3. Перевір локально

```bash
npm run dev
```

Пройдись по кроках:
1. Зайди у вкладку **"Працівники"** → додай працівника з відсотком.
2. Зайди у **"Робочий день"** → додай авто, обери цього працівника.
3. Перевір, що сума доходу і виплата порахувались правильно.
4. Відкрий картку працівника — переконайся, що бачиш статистику.
5. Зайди в **"Огляд"** — переконайся, що графік доходу й досі працює
   (він тепер підтягує дані автоматично з таблиці `work_days`, яку
   оновлює тригер).
